# NeuralOperator progress update — 20 September 2026

This note supersedes the status of the execution protocol in the main roadmap
for the current main baseline.

## Verified baseline

- main contains the spectral oracle, Burgers reference solver and dataset
  provenance, a minimal NumPy/SciPy FNO, a periodic interpolation and
  convolution baseline, and a separable linear DeepONet contract.
- All pull requests currently recorded for the repository are merged.
- The latest observed GitHub Actions test runs on main were successful.
- The repository remains a research reference implementation: it does not yet
  provide an autodiff backend, a nonlinear production DeepONet, a Rust kernel,
  or a validated performance advantage over a classical solver.

## Added in this tranche

The rollout evaluator makes the operator contract and the recursive test
explicit:

1. rollout_burgers_operator applies a one-transition operator repeatedly and
   rejects shape, type and non-finite-value violations.
2. evaluate_burgers_rollout reports per-step MSE and relative L2 error,
   finite-horizon transition residual, and mean/energy mismatch against the
   reference trajectory.
3. scripts/burgers_rollout_experiment.py trains the existing reference FNO
   and emits a JSON stability report over five recursive transitions.
4. Unit tests validate an exact solver-backed operator and invalid output
   handling.

The transition residual is intentionally documented as a discrete diagnostic;
it is not a continuous-time PINO objective.

## Next execution order

1. Add a deterministic train/validation/OOD split over initial-condition
   families, viscosity and forcing parameters.
2. Replace finite-difference SciPy training with an optional autodiff backend
   while retaining the NumPy oracle as the acceptance reference.
3. Add a genuinely nonlinear DeepONet and compare it with FNO, interpolation and
   local convolution using the same split and rollout metrics.
4. Add Darcy 2D and advection-diffusion truth solvers before any broad claim
   about resolution transfer.
5. Port only the numerically accepted kernels to SciRust/NNIS and retain
   cross-backend tolerance tests.
6. Add the repository licensing/provenance files aligned with the Memorithm
   source-available policy before publication or reuse outside the research
   workspace.
